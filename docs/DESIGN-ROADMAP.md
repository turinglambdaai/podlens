# PodLens 设计与路线图

给 PodLens 的产品/设计/跨平台规划。回答三个问题：这个软件应该长什么样；
macOS 和 Windows（以及未来的移动端）如何保持一致；每一步做什么、怎么验收。

状态标记：☐ 未开始 · ◐ 进行中 · ☑ 完成。

## 1. 产品定位

> 听得懂的英文播客——播放是听觉体验，逐句稿是视觉体验，翻译即时补位，总结收尾。

PodLens 解决三件事，缺一不可：

1. **人**：听懂英文播客——逐句对照稿 + 翻译 + 总结。
2. **平台**：播客产品的**真跨平台**——Apple Podcasts 只有 macOS/iOS，
   Android/Windows 一直是二等公民；PodLens 每端都是第一方原生（Rivet 定律），
   体验一致，包括未来的移动伴随端。
3. **Agent**：能被 agent 快速调用获取信息——CLI 全量出口 + JSON 契约，
   「这集里关于 X 说了什么、第几分钟」是逐句稿+时间戳结构的天然能力，
   人听和 agent 查共用同一份数据。

它不是「播客工作台」（工具），而是一个**阅读级的播客播放器**（产品）。
判断一切 UI 决策的标准：让「选一集 → 听懂它」的路径最短、最愉悦。

## 2. 审美参照系

**学 Apple Podcasts 的骨架，不学它的详情页。**

| 学什么 | 不学什么 |
|---|---|
| 三页范式：库 / 发现 / 播客详情（大封面+播放全部+单集列表）——用户零学习成本 | 详情页以「播放+章节」为中心——PodLens 的详情页以**逐句对照文本**为中心，这是唯一差异化，照抄它等于自废 |
| Now Playing 的全局性：mini player 常驻、点开即全屏 | 封面艺术橱窗式的富媒体堆砌——逐句稿区是**阅读排版**问题，靠字号/行高/对照节奏，不靠图片 |
| Chrome 克制：控件退后、内容为王 | 单平台的交互独占（触控条、独有手势）——两端一双手都好不好用才是标准 |

审美差的根因不是「没抄对对象」，而是「没定基准线」。基准线已定：
tokens 表（§4）管颜色与字号，「像不像 Apple」不是标准；标准是
**「同构检查表逐项一致 + 逐句稿阅读体验达到语言学习类产品
（双语字幕/对照阅读）的排版水准」**。逐句区的排版参照是双语字幕产品，
不是音乐播放器。

## 3. 设计原则

1. **逐句稿是主角**：详情区的核心体验是逐句对照——当前句高亮、点击句子跳播、
   双语/译文/原文切换不跳变。任何版本里它都必须是第一视觉层级。
2. **动作跟着对象走**：下载/转写/翻译/总结是单集的动作，放在单集上（行内、
   详情页），不放全局工具栏。全局只留「添加订阅」「设置」。
3. **状态可见但安静**：进行中的作业（转写/翻译）在单集行上给细进度，
   完成时轻提示；不弹窗打断。
4. **每端都是第一方原生**：不共享 UI 代码（Rivet 定律）。一致性来自同构的
   信息架构、共享 tokens、对齐的 i18n 键；控件、动效、弹层形态尊重平台习惯
   （macOS 用 sheet，Windows 用 ContentDialog）。
5. **诚实**：未配 API key 就明说；转写没跑完就不显示「已翻译」；成本由
   用户 key 承担，界面要让人预估（翻译句数 × 单价）。

## 4. 信息架构（两端同构）

```
┌─ 库 ─────────┬─ 单集 ───────────┬─ 详情 ─────────────────┐
│ 订阅列表     │ 封面+标题+日期    │ [逐句稿 | 总结] tab     │
│ + 添加订阅   │ 状态 chips        │ 逐句列表：              │
│ + 发现       │ 行内动作/进度     │   时间戳 原文           │
│ ──────────   │ （当前句高亮跟随）│   译文                  │
│ 设置（底部） │                   │ PlayerBar：播放/进度/倍速│
└──────────────┴───────────────────┴────────────────────────┘
```

- macOS：`NavigationSplitView` 三栏（已有）。
- Windows：`NavigationView`（左栏 Mica 背景）+ 单集 `ListView`（item 模板）
  + 详情 tab 化 + 底部 `PlayerBar`——**追平 macOS 已有结构**。
- 移动端（M4）：单栏自适应，库 → 单集 → 详情逐层下钻，PlayerBar 吸底常驻。

## 5. 视觉系统（design tokens）

真源在本文件（Rivet 不管 UI，见其 architecture.md「UI strategy」）；
两端各有一份薄常量文件引用这里，键名一致：

| token | 值 | 说明 |
|---|---|---|
| `accent` | `#C15F3C` | 陶土橙——站点、图标、应用同一品牌色 |
| `accent-soft` | `#F7E5DD` | 高亮底（当前句、选中态） |
| `bg` / `surface` | 跟随系统深浅色 | 不自造主题，用平台语义色 |
| `font-size` 阶 | 12 / 14 / 16 / 20 / 28 | caption / body / emphasized / title / large |
| `spacing` 阶 | 4 / 8 / 12 / 20 / 32 | 全部留白取自这一档 |
| `radius` | 8 / 12 | 控件 / 卡片 |
| 逐句行 | 原文 16 emphasized，译文 14 secondary | 时间戳 12 mono |

Windows：桥接为 XAML 资源字典（`Themes/Tokens.xaml`，深浅色两套）；
macOS：`DesignTokens.swift` 常量。新增颜色/字号必须先进这张表。

## 6. 路线图

### M1 — 两端一致性基线：Windows 追平 macOS ☑（v1.2.0，PR #3）

- [x] tokens 双端落地（§5 的表成为唯一真源）——`windows/Themes/Tokens.xaml` + `macos-host/.../DesignTokens.swift`
- [x] Windows 改 `NavigationView` 三区骨架；顶栏 CommandBar 删到只剩
      添加订阅/设置，其余动作移入单集行与详情
- [x] 单集 item 模板（标题/日期/时长/状态 chips），替换裸 ListBox
- [x] 详情区 tab 化（逐句稿 | 总结）+ EpisodeHeader（macOS 已有）
- [x] Windows PlayerBar 追平 macOS（播放/seek/倍速 1.0–2.0）
- [x] 空状态：订阅空/单集空/详情未选中三种占位（引导语 + 去发现页按钮）

**验收**：两端截图并排对照（`docs/screenshots/`），§3 检查表逐项同构；
首屏第一眼有品牌感（accent 出现、层级分明、无裸控件感）。

### M1.5 — 播放基础补课：系统媒体集成 + 播放控件 ☑（podlens#4，未发版）

对齐 Apple Podcasts 的「听」轴基础件（逐句稿差异化的「读」轴不追它）：

- [x] macOS 媒体键 + 控制中心 Now Playing（`MPRemoteCommandCenter` +
      `MPNowPlayingInfoCenter`，带节目封面）；Windows SMTC（任务栏悬浮窗、
      蓝牙耳机按钮，手动接线，1 Hz 时间线）
- [x] 两端 PlayerBar 加 ±15/30s skip；键盘：空格播放暂停、⌘←/⌘→（Windows
      Ctrl+←/→）seek——文本框聚焦时不抢键
- [x] 倍速扩到 3.0×（对齐 Apple 上限）；macOS 修 1.25× 显示成 1.2× 的格式化
- [x] 睡眠定时器（5–90 分钟，到点暂停）
- [x] macOS 跟随滚动只在活动句变化时触发（原先每 5s 重滚）；进度保存节流
- [x] 修 Windows 播放自 M1 起不可用（`MediaPlayer` 从未构造，调用即抛
      E_POINTER 显「播放失败」）

**验收**：两端媒体键/悬浮窗可控制播放并显示单集元数据；空格/快捷键/睡眠
定时可用；`raco rivet build` 两端绿。

### M2 — 逐句稿即产品：核心体验 ☑（v1.2 起逐项落地；跟随滚动修复在 M1.5）

- [x] 逐句列表控件：句 = 行（时间戳 + 原文 + 译文）——v1.1 两端已是行式列表
- [x] 当前播放句高亮 + 自动跟随滚动；点击句子 seek——跟随逻辑 2026-10-02
      改为半秒观察器 + 仅活动句变化时滚动（M1.5）
- [x] 双语/译文/原文切换零跳变（同一列表切显隐，不重建）
- [x] 总结页卡片化：一句话总结 / 要点列表 / 值得记的话 / 话题标签
- [x] 性能：两端列表控件均原生虚拟化（SwiftUI List / ListView），
      千句级单集可滚

**验收**：播放中逐句跟随流畅；点击跳播 < 200ms；两端交互逐项一致。

### M3 — 实用性闭环 ☑（2026-10-02，批次 B 全量落地，podlens#5）

- [x] 首启引导：无订阅时默认进入发现页（macOS；2026-10-01）——发现页已支持
      全目录搜索（iTunes Search API，权威 feedUrl，`catalog-search` RPC）
- [ ] 预置推荐单集可一键试听（低优先级，未做）
- [x] 「听懂这集」一键流水线：`episode-pipeline` RPC（下载→转写→翻译→
      总结串联，完成阶段自动跳过），`job-progress` 驱动单集行内进度——
      **契约变更随 v1.3.0 三端同发**
- [x] 继续上次：`resume-last` RPC + 两端启动恢复（选中不自动播放）
- [x] 成本可见：`episode-estimate` RPC + 两端动作行下方的预估行 +
      CLI `estimate`
- [x] Agent 出口补齐：`podlens export <episode>`（带 @mm:ss 锚点的
      Markdown 逐句稿+总结）、`podlens find <terms>`（跨订阅全文检索，
      句级时间戳定位）；另有 `pipeline` / `done` 两个新命令

**验收**：新用户 3 分钟内完成「订阅 → 听懂一集」全流程，全程无文档；
agent 用两条 CLI 命令完成「订阅并取回某集的中文要点」。

### M3.5 — 播放与库管理补全 ☑（2026-10-02，podlens#5，与批次 B 同发）

对齐 Apple Podcasts 的剩余日用差距（「读」轴差异化不动）：

- [x] Show notes：`episode-list` 行带单集 description（第 11 列），两端
      详情头显示——数据早就在解析，只是从未端出来
- [x] 自动连播：播完自动进入同 feed 下一集（不假装有 Up Next 队列）
- [x] 标记已听/未听：`episode-set-done` RPC + 详情按钮 + 行右键菜单；
      未听同时清零进度
- [x] 未听角标：`feed-list` 行带未听数（第 8 列），侧栏红点计数
- [x] 章节标记（Podcasting 2.0 `<podcast:chapters>`）：抓取+缓存 +
      `episode-chapters` RPC + 两端上一章/下一章按钮（无章节时隐藏）；
      分章总结不做（N 倍 LLM 账单，等真实需求）
- [x] 自动刷新：两端每 30 分钟后台刷新；macOS 新单集走系统通知，
      Windows 状态行提示（toast 需要包身份，诚实不做）

**验收**：两端 CI 绿 + 实机过一遍「订阅→一键听懂→连播→标记」全流程。

### M4 — 移动端伴随（与 Rivet 一起成长）☐

形态定调：**手机 = 遥控 + 阅读器**。桌面宿主是引擎（下载/转写/翻译在其上），
手机在同一网络内：浏览逐句稿、总结，遥控播放/seek/倍速。不做手机端全功能
（转写翻译吃 key 与流量，桌面是正确场所）。

依赖的 Rivet 成长（先立 issue 设计，实现落 rivet）：
- [ ] 网络传输的 RVT1/RivetDevice 通道（现状只有 in-process 与
      WatchConnectivity，且方向是「后端在手机」——需要反转为
      「桌面宿主暴露类型化设备 API」+ TCP/WebSocket 传输）
- [ ] iOS：SwiftUI 壳 + 复用现有 Swift RVT1 client（基线 iOS 16）
- [ ] Android：复用 Kotlin client，待传输层就绪后排期

**验收**：手机在局域网内完成「看到正在播放的逐句稿 + 遥控播放」。

### M5 — 沉淀回 Rivet ☐

- [ ] M4 的网络设备通道按 rivet 的协议/测试标准整理成 PR
- [ ] PodLens 的跨端一致性方法（tokens 表 + 同构检查表 + i18n 对齐）
      写成 rivet 文档案例，供后续 Rivet 产品复用
