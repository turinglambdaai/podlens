# PodLens 设计与路线图

给 PodLens 的产品/设计/跨平台规划。回答三个问题：这个软件应该长什么样；
macOS 和 Windows（以及未来的移动端）如何保持一致；每一步做什么、怎么验收。

状态标记：☐ 未开始 · ◐ 进行中 · ☑ 完成。

## 1. 产品定位

> 听得懂的英文播客——播放是听觉体验，逐句稿是视觉体验，翻译即时补位，总结收尾。

PodLens 不是「播客工作台」（工具），而是一个**阅读级的播客播放器**（产品）。
判断一切 UI 决策的标准：让「选一集 → 听懂它」的路径最短、最愉悦。

## 2. 设计原则

1. **逐句稿是主角**：详情区的核心体验是逐句对照——当前句高亮、点击句子跳播、
   双语/译文/原文切换不跳变。任何版本里它都必须是第一视觉层级。
2. **动作跟着对象走**：下载/转写/翻译/总结是单集的动作，放在单集上（行内、
   详情页），不放全局工具栏。全局只留「添加订阅」「设置」。
3. **状态可见但安静**：进行中的作业（转写/翻译）在单集行上给细进度，
   完成时轻提示；不弹窗打断。
4. **每端都是第一方原生**：不共享 UI 代码（Rivet 定律）。一致性来自同构的
   信息架构、共享 tokens、对齐的 i18n 键；控件、动效、弹层形态尊重平台习惯
   （macOS 用 sheet，Windows 用 ContentDialog）。
5. **诚实**：未配 API key 就明说；转写没跑完就不显示「已翻译」；成本由
   用户 key 承担，界面要让人预估（翻译句数 × 单价）。

## 3. 信息架构（两端同构）

```
┌─ 库 ─────────┬─ 单集 ───────────┬─ 详情 ─────────────────┐
│ 订阅列表     │ 封面+标题+日期    │ [逐句稿 | 总结] tab     │
│ + 添加订阅   │ 状态 chips        │ 逐句列表：              │
│ + 发现       │ 行内动作/进度     │   时间戳 原文           │
│ ──────────   │ （当前句高亮跟随）│   译文                  │
│ 设置（底部） │                   │ PlayerBar：播放/进度/倍速│
└──────────────┴───────────────────┴────────────────────────┘
```

- macOS：`NavigationSplitView` 三栏（已有）。
- Windows：`NavigationView`（左栏 Mica 背景）+ 单集 `ListView`（item 模板）
  + 详情 tab 化 + 底部 `PlayerBar`——**追平 macOS 已有结构**。
- 移动端（M4）：单栏自适应，库 → 单集 → 详情逐层下钻，PlayerBar 吸底常驻。

## 4. 视觉系统（design tokens）

真源在本文件（Rivet 不管 UI，见其 architecture.md「UI strategy」）；
两端各有一份薄常量文件引用这里，键名一致：

| token | 值 | 说明 |
|---|---|---|
| `accent` | `#C15F3C` | 陶土橙——站点、图标、应用同一品牌色 |
| `accent-soft` | `#F7E5DD` | 高亮底（当前句、选中态） |
| `bg` / `surface` | 跟随系统深浅色 | 不自造主题，用平台语义色 |
| `font-size` 阶 | 12 / 14 / 16 / 20 / 28 | caption / body / emphasized / title / large |
| `spacing` 阶 | 4 / 8 / 12 / 20 / 32 | 全部留白取自这一档 |
| `radius` | 8 / 12 | 控件 / 卡片 |
| 逐句行 | 原文 16 emphasized，译文 14 secondary | 时间戳 12 mono |

Windows：桥接为 XAML 资源字典（`Themes/Tokens.xaml`，深浅色两套）；
macOS：`DesignTokens.swift` 常量。新增颜色/字号必须先进这张表。

## 5. 路线图

### M1 — 两端一致性基线：Windows 追平 macOS ☐

- [ ] tokens 双端落地（§4 的表成为唯一真源）
- [ ] Windows 改 `NavigationView` 三区骨架；顶栏 CommandBar 删到只剩
      添加订阅/设置，其余动作移入单集行与详情
- [ ] 单集 item 模板（标题/日期/时长/状态 chips），替换裸 ListBox
- [ ] 详情区 tab 化（逐句稿 | 总结）+ EpisodeHeader（macOS 已有）
- [ ] Windows PlayerBar 追平 macOS（播放/seek/倍速 1.0–2.0）
- [ ] 空状态：订阅空/单集空/详情未选中三种占位（引导语 + 去发现页按钮）

**验收**：两端截图并排对照（`docs/screenshots/`），§3 检查表逐项同构；
首屏第一眼有品牌感（accent 出现、层级分明、无裸控件感）。

### M2 — 逐句稿即产品：核心体验 ☐

- [ ] 逐句列表控件：句 = 行（时间戳 + 原文 + 译文），替换纯文本流
- [ ] 当前播放句高亮 + 自动跟随滚动；点击句子 seek
- [ ] 双语/译文/原文切换零跳变（同一列表切显隐，不重建）
- [ ] 总结页卡片化：一句话总结 / 要点列表 / 值得记的话 / 话题标签
- [ ] 性能：一小时单集（~1000 句）滚动与跟随不卡（虚拟化列表）

**验收**：播放中逐句跟随流畅；点击跳播 < 200ms；两端交互逐项一致。

### M3 — 实用性闭环 ☐

- [ ] 首启引导：无订阅时默认进入发现页；预置推荐单集可一键试听
- [ ] 「听懂这集」一键流水线：backend 新增 pipeline RPC（下载→转写→
      翻译→总结串联），`job-progress` 驱动单集行内进度——**backend
      契约变更，三端同发**
- [ ] 继续上次：启动恢复上次单集与播放位置
- [ ] 成本可见：转写/翻译前显示预计句数与字符量

**验收**：新用户 3 分钟内完成「订阅 → 听懂一集」全流程，全程无文档。

### M4 — 移动端伴随（与 Rivet 一起成长）☐

形态定调：**手机 = 遥控 + 阅读器**。桌面宿主是引擎（下载/转写/翻译在其上），
手机在同一网络内：浏览逐句稿、总结，遥控播放/seek/倍速。不做手机端全功能
（转写翻译吃 key 与流量，桌面是正确场所）。

依赖的 Rivet 成长（先立 issue 设计，实现落 rivet）：
- [ ] 网络传输的 RVT1/RivetDevice 通道（现状只有 in-process 与
      WatchConnectivity，且方向是「后端在手机」——需要反转为
      「桌面宿主暴露类型化设备 API」+ TCP/WebSocket 传输）
- [ ] iOS：SwiftUI 壳 + 复用现有 Swift RVT1 client（基线 iOS 16）
- [ ] Android：复用 Kotlin client，待传输层就绪后排期

**验收**：手机在局域网内完成「看到正在播放的逐句稿 + 遥控播放」。

### M5 — 沉淀回 Rivet ☐

- [ ] M4 的网络设备通道按 rivet 的协议/测试标准整理成 PR
- [ ] PodLens 的跨端一致性方法（tokens 表 + 同构检查表 + i18n 对齐）
      写成 rivet 文档案例，供后续 Rivet 产品复用

## 6. 本文档的维护

每个 M 完成时勾选并附 release/PR 链接；tokens 表变更必须进 CHANGELOG
（视觉变化用户可感）。移动端形态若推翻重议，先改 §5-M4 再动工。
